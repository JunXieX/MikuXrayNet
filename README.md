# MikuXrayNet

## 声明

作者：JunXieX　|　MikuMC系列插件交流群：1105054380　|　非开源项目，请勿二次分发

本项目为 MikuMC 服务器原创插件，公开给大众免费使用。MikuMC 服务器与作者 JunXieX 享有项目著作权。

---

MikuMC 服务器原创的 **反矿透 + 带宽优化** 双模块插件，适配 Paper 26.2+ / Folia，基于 Java 25。

一句话：**让透视端看不到真矿，同时让服务端少发封包。**

---

## 一、功能特性

### 反矿透（AntiXray）

把埋在地下、玩家看不见的矿物与容器替换成普通方块后再发给客户端；等玩家真的走近、且真的能看见时，再还原成真实方块。

| 能力 | 说明 |
| --- | --- |
| 掩埋伪装 | `all` 模式按目标表伪装，默认通过 `proximity.keep-exposed-ores` 保留已确认露面的矿；`enclosed` 模式只伪装六面都被遮挡的目标方块。支持按权重伪装、按高度分层和使用下方方块作为伪装材质 |
| 按维度配置 | 主世界 / 地狱 / 末地各自配置「隐藏什么、伪装成什么、怎么伪装」；末地默认关闭。支持 `tag(...)` 写法（如 `tag(diamond_ores)` 自动展开为全部钻石矿） |
| 世界黑名单 / 逐世界覆盖 | 主城、副本等不想伪装也不想省带宽的世界加入独立文件 `blacklist.yml` 即可**同时豁免反矿透与带宽优化**；也可以只给某个世界单独覆盖反矿透设置 |
| 邻近显形 | 已露面的矿物首次加载就显示真材质。挖去遮挡物时优先还原破口里的矿；若当前目标仍待同步，会先更新材质再让下一次挖掘生效。 |
| 视锥剔除 | 周期巡检优先处理视野内候选，减少不必要的显形包；近身、挖掘和区块下发另有即时补充路径 |
| 磁盘缓存 | 改写结果落盘，重启后直接复用，省掉重复判定与编码；区块内容或配置变化会自动失效重写，磁盘异常自动降级为纯内存运行 |
| 引导绕过 | 持有 `mikuxraynet.bypass` 权限的玩家看到真实世界（方便管理员排查）。该权限在玩家**进入服务器时判定一次**，运行中授予/撤销需让玩家重新进入才生效 |
| 判定纠错 | 内置遮挡判定提供的「人工纠正表」，发现某方块被误判时填注册名即可修正 |

默认隐藏清单（可在配置里自由增删）：主世界 16 种矿石 + 3 种粗金属块 + 刷怪笼 + 苔石；地狱为下界残骸 + 下界金矿 + 刷怪笼（默认不含地狱石英矿——分布广、价值低，藏了只会到处是假石头；也默认不含箱子——容器是方块实体，伪装后显形只能补方块状态，需要时自行加回）。

### 带宽优化（Bandwidth）

在**不改变玩家看到的内容**的前提下减少封包数量与体积。

| 能力 | 说明 |
| --- | --- |
| 零位移包取消 | **纯位移**包在位移全为 0 时直接不发（可白名单豁免盔甲架、展示框等）；**朝向包一律放行**——朝向是绝对量化角，「全 0」是合法的正南/平视，按全 0 取消会导致客户端朝向不同步 |
| 方块变更合并 | 玩家周围短时间内的多条方块变更合并成一条批量包；挖掘/放置半径内原包立即放行，不影响手感 |
| 调色板位宽预算 | 防止「替换方块导致区块封包膨胀」，并顺带清理无用的调色板条目，多数情况下封包更小 |
| 实体剔除 | 剔除被墙完全挡住的实体，带强制可见距离兜底（玩家自身、其它玩家、烟花始终放行）；静止实体自动跳过高频复检，把射线预算让给真正在动/刚被挡住的实体 |
| 视锥剔除 | 在「被墙挡住」之外，再剔除**位于视野之外、且距离超过设定值**的实体（玩家背后 / 侧后根本看不到的实体），连射线都省下；玩家转头后一个复检周期内自动补发。视锥数学与反矿透侧共用同一套，FOV 默认取客户端上限 110°，保证把 FOV 拉满也看不到被剔除的实体 |
| AFK 降级 | 挂机玩家按距离丢弃粒子与方块破坏动画等低价值包 |
| 高延迟降视距 | 延迟持续超标的玩家自动降低视距，恢复正常后还原 |
| 运行摘要 | 定时在控制台输出一行精简摘要，随时掌握省包情况 |

## 二、注意事项

1. **依赖**
   - **PacketEvents 2.13.0+（必需）**：缺失时插件直接禁用。
   - **ProtocolLib 5.3.0+（反矿透必需）**：它是唯一的封包拦截通道；缺失时插件仍能加载，但反矿透停用，依赖封包通道的三项带宽子模块（零位移取消 / 方块变更合并 / AFK 降级）不接线；**实体剔除与高延迟降视距不因缺少 ProtocolLib 而停用**（实体剔除此时只剩配置允许的子项：视锥看 `entity-culling.frustum.enabled`，射线遮挡要遮挡数据），调色板压缩需要区块改写、随反矿透一并停用。`/mxnet status` 的「实际未注册：…」会逐项写出未接线的模块与原因。
   - 可选兼容：ViaVersion / ViaBackwards / Geyser-Spigot（自动识别加载顺序）。
   - **Spark（可选，不装也能用）**：装了会给 `/mxnet dump` 多一份 30 秒全线程性能记录；不装则该命令自动按 10 秒本地采样。Spark 不写进 `paper-plugin.yml` 的依赖段，既不是硬依赖也不扩权，Paper 与 Folia 都照常加载。
2. **运行环境**：Paper 26.2+ 或 Folia 26.x，**Java 25**；不支持 Java 17 及以下。Folia 兼容（世界访问一律走区域调度器），且已在 `paper-plugin.yml` 显式声明 `folia-supported: true`。**只支持 Paper 系核心**（Paper / Leaf / Folia）：jar 内只附带 `paper-plugin.yml`，不再附带传统 `plugin.yml`，纯 Bukkit/Spigot 核心无法加载本插件。
3. **配置文件**：首次启动自动生成 `antixray.yml`、`bandwidth.yml` 与 `blacklist.yml`（世界黑名单，对两个模块同时生效），全部带中文注释，按服主视角说明每项作用；改完执行 `/mikuxraynet reload` 即时生效（少部分项需重启，命令会提示）。
4. **安全上下限**：关键项都设了安全区间，配超范围会被自动钳制到安全值并在控制台**提示一次**。下限（例：视锥角度 110°、视锥豁免距离 16 格、降视距下限 6 格、磁盘缓存过期 1 天、实体视锥 FOV 30°）用来避免「玩家看得见假方块」或「看得到实体却被剔除」；上限（例：合并窗口 200ms、复检周期 40 tick、降视距幅度 4 格、邻近显形距离 128 格）用来避免手滑配出「明显延迟」或「拖慢服务器」的数值。
5. **缓存会失效重建**：修改隐藏清单、伪装方块、遮挡规则、`remove-block-entities`、`blacklist.yml` 的世界名单、`bandwidth.yml` 的 `palette` 段（位宽预算 / 自检）、磁盘缓存的 `zstd-sha256` 等会改变改写结果的项，都会让磁盘缓存与内存缓存整体失效并自动重建一次；此外区块边界依赖的**邻块贴边快照内容**变化时，也会让对应条目自然失效重写。以上均属正常现象，之后命中率恢复。
6. **磁盘缓存占用**：条目数、单文件大小与区域文件数默认都**不限制**（磁盘由你自备，缓存越多命中率越高；内存只与 `bucket-cache-size` / `idle-close-seconds` 有关，不随总条目增长）。只有真正被改写的区块才保存完整字节，无需改写的区块只保留坐标数与遮挡数据，因此实际占用通常远低于「条数 × 单块大小」的估算。过期时间从**写入时刻**起算，应大于两次开服的间隔（默认 7 天）。**插件版本变化时旧缓存会整体清空重建**（同版本重启不清），避免跨版本缓存内容不一致；需要控盘时再调 `max-entries` / `max-file-size-mb` / `max-region-files`。另可用 `disk-cache.zstd-sha256` 对自动下载的压缩库做摘要校验（默认留空＝不校验，但仍会打印实际 SHA-256 供你填入）；若缓存目录被另一个服务端实例同时占用，本实例会自动停用「被占用文件」的磁盘缓存（只提示一次，功能不受影响）。**磁盘水位只看同量纲**：`/mxnet status` 只在「同时打开的句柄数 / `max-open-files`」到 90% 或「条目数 / 文件数完全没设上限」时提示；`bucket-cache-size` 是每个**已打开文件**缓存的条目数（安全上限 64），与句柄上限不是同一量纲——常驻内存约等于「同时打开的句柄数 × 每文件条目数」，把它调到大于等于 `max-open-files` 只会成倍放大每文件占用、并不改变句柄是否够用。磁盘缓存参数（含 `max-open-files`）改动后都要**重启**才生效。
7. **给主城减负**：把主城 / 副本世界加入 `blacklist.yml` 的 `world-blacklist`，可**同时**跳过反矿透（省 CPU，也避免建筑被伪装）与带宽优化（不做实体剔除、变更合并等）；也可只单独覆盖反矿透设置（`antixray.yml` 的 `world-overrides`），此时带宽优化照常工作。黑名单优先级高于 `world-overrides`。
8. **全程 fail-open**：任何超时、队列积压或异常都会放行原包，绝不卡住玩家或客户端加载。
9. **自带诊断**：`/mxnet status` 查看完整统计，`/mxnet dump` 导出诊断文件；状态里有「安全阀触发」计数，正常运营下应恒为 0，非 0 请带 dump 反馈。
   - **两种 dump**：`/mxnet dump` 默认采样 **30 秒**（每 0.5 秒一个样本），并在同一窗口内请求一次 **Spark 全线程性能记录**；采样结束照常写出本地诊断文件，Spark 性能记录会上传至 Spark，命令回显里给出官方链接。`/mxnet dump local` 是原来的 **10 秒纯本地采样**：不请求 Spark、不上传任何内容。第二个参数只认 `local`，写别的值会回用法提示，不会静默按默认跑。
   - **没装 Spark 也能用（三档，别混读）**：① **未检测到 Spark**——命令一进来就按 **10 秒**本地采样跑完，不请求 Spark、不上传，回显与 dump 都点名「未检测到 Spark」；② **Spark 在但明确没启动**（正忙或启动失败）——一收到「未执行」就把数值窗口**收回到 10 秒**（通常 1~2 秒内就能判定，整条约 10 秒出文件），并追加一句「Spark 未启动（原因已写进 dump），本次采样按 10 秒收尾」；③ **已启动但超时**——数值窗口仍是 **30 秒**，照常写出 dump，只在 Spark 段写「超时：等待 65 秒仍未取到结果」、链接缺省（这时性能记录是真的在跑，砍窗口反而等于谎报口径）。无论哪一档，回显与转储里的段标题写的都是**实际**时长，不会出现「说 30 秒、实际 10 秒」；整条命令从发起算起最多约 **65 秒**。
   - **Folia 上要另装 spark 插件**：Paper 内置的 spark 被上游补丁在 Folia 端显式禁用，Folia 上必须另外安装独立的 spark 插件本功能才可用（Paper 端可直接用内置 spark）；没装时 `/mxnet dump` 会给出中文理由并退回 10 秒本地采样，不上传任何数据。
   - **不打断你手工开的 Spark**：只有在服务器上**已有手工 Spark 采样正在进行**时，本插件才不 stop、不 cancel 它，并在回显与 dump 里写明理由；拿不到「本次采样已启动」的确认时，转储按本地名义窗口记录指标并注明实际时长——这段**不能**当作与 Spark 采样精确重叠的同一窗口。
   - **注意：Spark 自己的后台采样器会被停掉（真实副作用）**：若你在 Spark 里开着**内置后台采样器**（background profiler），执行 `/mxnet dump` 时 Spark 会先停掉它，而且**超时结束后不会自动恢复**（Spark 侧只有 `/spark profiler stop` 分支才会重启后台采样器）；也就是说它会一直停到你重启服务器。**规避方式**：不需要 Spark 剖析时用 `/mxnet dump local`，或采样完重启一次服务器。dump 文件里有一行「说明：」写明这一点。这与上一条「不打断你手工开的 Spark」**不矛盾**：被停的是 Spark 自己的后台采样器；而服务器上正在跑的手工**前台**采样，我们一律 fail-soft 等待、不 stop 也不 cancel。
   - **上传范围与可见性**：自动上传的只有这次生成的 Spark 性能文件，**不上传**插件转储、配置内容或任何令牌；dump 文件本身始终留在本地。链接形如 `https://spark.lucko.me/<key>`；若 `plugins/spark/config.json` 里配了 https 的 `viewerUrl` / `bytebinUrl`，则改用运营者自己的端点。链接的可见性由 Spark 侧决定，能拿到链接的人即可访问，转发给他人前请自行确认对方可信。
   - **回显只给执行者**：dump 的结果（含 Spark 链接）只回显给执行这条命令的人，不广播、也不写入服务端日志；权限沿用 `mikuxraynet.dump`，没有新增配置项。
   - **读数口径**：读数是**同一窗口内的首末差分**（`/mxnet dump` 的「运行采样」段默认 30 秒；`/mxnet dump local` 与未装 Spark 时的回退都是 10 秒），跨窗口的两次采样不能当同一时刻比较。另有三处口径要看后缀：磁盘缓存的「命中」是「读到条目」，被内容校验作废的不计入「有效」；「负载被拒」会分两类写——源指纹不一致＝区块内容变了（正常失效，重写覆盖即可）、信封/数据故障＝负载损坏或格式不符（需要清缓存并查盘）；同样，「内容已变」拆成「源字节已变 / 缺位图」（缺位图＝遮挡建表在这批区块上失败，该区块会一直藏住矿），在途补发拆成「观测缺失 / 淘汰 / 区域失败 / 覆盖丢失」并附「写出确认」次数。括号里若出现「子项与总数分别读取，无法原子比较」，那是聚合值与子项分别计数导致的读数误差（面板只在 `status`/`dump` 时读取，不加锁、也不会为它阻塞封包线程），不代表故障；带 dump 反馈即可。另外，1.34.13 及更早版本的「登记或补发未完成」是混合总数（含脏段截断等），与新版本的四类逐项对照会失真——升级前后这两个数不要直接比较。

## 三、技术亮点

- **原生封包改写，不碰 NMS**：直接在出站区块封包上做纯字节级编解码（复用 Netty ByteBuf），服务端版本升级不需要改代码，也不会因为内部类变动而崩服。
- **真异步扣包，网络线程零计算**：通过 ProtocolLib 的异步通道拦截封包，回调只登记任务后立即让出；解码、遮挡判定、重编码全部在自有线程池完成，并设有队列上限与处理超时——积压的结果是放行，而不是卡玩家。
- **前置只当「启动期字典」用**：PacketEvents 仅在启动时构建方块状态位图（空气 / 流体 / 遮挡 / 伪装权重），此后热路径零引用，不给封包链路增加任何额外开销。
- **自研磁盘缓存格式**：32×32 区块一个区域文件、**一个区块一条独立追加记录**（改 1 个区块只重压 1 条，不再重压整桶）+ zstd 压缩（服务端缺失时自动回退内置压缩，并支持自动下载与镜像源）；每条负载携带「原始区块字节指纹 + 配置指纹 + 邻块快照内容指纹」多重校验，跨重启安全复用，内容、配置或邻块状态一变立刻自动重写。
- **内容指纹走硬件指令**：区块内容指纹（每个区块封包都要校验一次）改用 JDK 内置的 CRC32C + CRC32 两个不同多项式组合（仍是 64 位强度）。本机实测 200 KB 负载从标量 FNV-1a 的约 143 µs 降到约 8.8 µs（1.4 GB/s → 22 GB/s，约 16 倍），且**未**采用「抽样指纹」——抽样会漏检未采样区间的单字节改动，那等于放行按旧内容改写的新区块，属不可接受的正确性风险。
- **显形索引用得省、发得也省**：伪装坐标按区块共享（内存占用与玩家数无关），已显形坐标按玩家记录（天然有界）；一个巡检周期的显形数据用 Paper 原生批量包一次性发出，通常只产生「涉及区块段数」个包。
- **遮挡判定走异步位图**：反矿透显形与实体剔除共用同一套遮挡判定（区块级遮挡位图 + 专用线程池异步射线），候选点只取暴露面，**「只发玩家真正看得见的」**，既省带宽也不隔着墙泄露；判定全程在网络线程之外完成，堵塞结果是放行而非卡玩家。
- **实体优化也守线程纪律**：视锥剔除复用反矿透侧同一套视锥数学，并在每个玩家所属线程上做**纯数学复判**（不打射线），据此实现「转头后 ≤ 1 个复检周期补发」，全程不触碰任何实体 API。
- **面向 Folia 的线程纪律**：Paper / Folia 双平台启动期自动判定；世界访问一律走区域调度器，跨区域访问严格规避，区域化多线程下同样稳定。
- **停用/热重载也做清理**：Bukkit 会在 `onDisable` 之前就把插件置为 disabled，导致此时任何调度都会被拒绝——本插件在停用期改为**同步恢复**被隐藏的实体与降过的视距（跨区域时明确提示需重登），不会留下「看不见的怪」或「被降死的视距」。
- **内存纪律**：缓存键只含世界名与坐标等基本类型，绝不持有 `World` / `Chunk` / `Player` / 封包对象，世界卸载即整体释放。
- **邻块快照位打包**：用于消除区块边界漏洞的邻块贴边数据按每格 1 bit 存储（单条约 3 KB），并按列裁剪到地表高度；只在需要六面判定的模式下才抓取，默认模式完全不抓。
- **可观测性**：改写 / 显形 / 实体隐藏 / 磁盘缓存 / 线程池水位 / 安全阀计数全部可在 `/mxnet status` 与 dump 中查看，任何异常都有一处可追的证据。

---

### 挖矿时的方块外观

默认开启 `proximity.keep-exposed-ores`：即使选择 `all`，已露面的矿也会在区块首包显示真实状态，完全包住的矿和其它伪装目标仍按原规则处理。此项修改后重启生效。连续挖掘优先还原破口后的可见矿，不用逐块对准；少数还未同步的目标，首次点击会先还原材质，不扣耐久、不发掉落。

### 破坏邻域显形

在 `antixray.yml` 的 `proximity.instant-reveal.break-sweep` 下设置 `radius`（默认 4，范围 1–8 格）。半径以被挖掉的方块为中心，只向破坏者还原可见方块。`max-per-tick` 默认 32 格，超出检测额度的部分分 tick 处理。关闭 `break-sweep.enabled` 不影响原来的即时显形。

## 四、安装

1. 将 `MikuXrayNet-x.y.z.jar` 放入 `plugins/`。
2. 确保已安装前置 **PacketEvents** 与 **ProtocolLib**。
3. 启动服务端，自动生成三份带中文注释的配置（`antixray.yml`、`bandwidth.yml`、`blacklist.yml`）；按需修改后 `/mikuxraynet reload` 生效。

## 五、命令与权限

| 命令 | 说明 |
| --- | --- |
| `/mikuxraynet status`（别名 `/mxnet`、`/mxr`） | 查看运行状态：依赖、平台、改写与显形统计、实体隐藏、磁盘缓存命中率、线程池水位 |
| `/mikuxraynet dump` | 采样 30 秒并请求一次 Spark 全线程性能记录，写出本地诊断文件、回显路径与 Spark 官方链接（未装 Spark 时自动退回 10 秒本地采样） |
| `/mikuxraynet dump local` | 10 秒纯本地采样，不请求 Spark、不上传任何内容 |
| `/mikuxraynet reload` | 热重载三份配置并重建周期任务 |

| 权限 | 说明 | 默认 |
| --- | --- | --- |
| `mikuxraynet.admin` | 管理命令总权限（父节点，含 status / dump / reload） | OP |
| `mikuxraynet.status` | 查看运行状态与统计 | OP |
| `mikuxraynet.dump` | 导出诊断转储 | OP |
| `mikuxraynet.reload` | 热重载配置 | OP |
| `mikuxraynet.bypass` | 绕过反矿透，看到真实世界（进入服务器时判定一次） | 无 |

三个子命令权限可**单独授予**：只给 `mikuxraynet.status` 的玩家，补全里只出现 `status`、也只能执行它；`mikuxraynet.admin` 是这三者的父节点，授予 admin 即同时授予三者。
